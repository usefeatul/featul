# Security remediation and release checks

Updated 10 October 2026. This records the fixes following [the security review](../security_best_practices_report.md). The user confirmed `PROD_DATABASE_URL` as the release database. Production and development authentication migrations are applied; both Vercel releases passed their production builds and smoke checks and were promoted after explicit user approval. Public domains now serve the reviewed releases. The legacy private-content attachment reference was migrated and its public original removed after verification.

## Implemented

| Review finding | Change |
| --- | --- |
| 01: Consent proxy SSRF / credential forwarding | Fixed upstream origin and path, rejected URL/traversal segments, removed cookies and authorization from forwarded headers, disabled redirects, bounded request/response bodies and request duration. |
| 02: Credentialed CORS | Removed permissive inner middleware. The outer policy strips inherited CORS headers and grants access only to trusted origins, including on error responses. |
| 03: Private content disclosure | Legacy detail routes require membership. Public queries require active, visible, public boards and published posts. Internal/hidden comments and private metadata are excluded. Public board counts also exclude drafts. |
| 04: Private response caching | Session-dependent search/count/comment results and credentialed API responses use `private, no-store`. Purge previously cached responses when deploying. |
| 05: Vulnerable dependencies | Updated Next.js, Better Auth and plugins, runtime/tooling dependencies, and lockfile; removed unused vulnerable dependencies. Adapted auth rate storage, account unlinking, two-factor setup, consent UI, and editor APIs. Added the required two-factor schema migration. Removed an unused organization plugin that referenced tables this app does not have; custom workspace membership remains authoritative. |
| 06: Revoked-author mutations | Post/comment update and deletion require current parent-resource access before author/moderator permissions. Comment editing respects post locks. |
| 07: Public private-content attachments | New post/comment images require a separate private bucket. Canonical image URLs resolve resource access on every read. Upload previews use short-lived signed URLs. Reference reuse checks prevent outsiders attaching an existing private image to public content. Cleanup supports private objects; an explicit legacy migration script is included. **The inventoried legacy content object has now been migrated; its old public URL returns 404.** |
| 08: AI spending / runaway generation | Atomic Redis reservations enforce monthly workspace generation allowances (Free 10, Starter 100, Professional 500), five starts per minute, one active generation, a 90-second provider timeout, cancellation, and a 256 KiB request-body limit. Failed/aborted requests still consume a reservation. Missing/unavailable usage tracking fails closed. **These are request allowances, not measured dollar/token billing; configure provider spending caps.** |

Also enabled Next build type checking, repaired the lint failure, added regression tests to CI, disabled default Sentry PII/session replay, removed email/name analytics identification, and removed production `unsafe-eval`. Inline script allowances remain. Comment payload arrays and post content now have explicit bounds. Comment creation, reactions, parent/post counters and activity now commit atomically. Widget replies reject unpublished parents. Client IP limiting trusts Vercel-owned forwarding headers on Vercel; other production hosts must explicitly configure their trusted proxy header. Legacy public-bucket garbage collection is disabled by default because that bucket is shared across databases.

Request-count AI quotas should evolve to token/cost accounting if strict per-workspace billing budgets are required. Review telemetry retention and consent in the deployed provider settings.

Verification logs and the release receipt are preserved in the owner-only local release archive. Temporary QA PostgreSQL, HTTP proxy, application server and Stripe listener have been stopped. The disposable Stripe test clock/customer/subscriptions were removed. Live deployments were promoted with explicit user approval. Fresh pre-cutover backups and the attachment rollback manifest are preserved alongside the earlier backups. If rolling the application back, retain the protected delivery route; do not restore public attachment URLs or public copies as a routine rollback.
