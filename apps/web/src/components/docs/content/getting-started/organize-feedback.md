## Boards, tags, and statuses

Use three layers to keep feedback usable:

1. **Boards** – One home for each request (Features, Bugs, a product area)
2. **Tags** – Labels that can apply across boards
3. **Roadmap status** – Where the request sits in your pipeline

## Tags

Apply tags from a request, or create them in **Settings → Feedback**. New workspaces include starter tags such as Guide, UI, Design, Security, Bugs, and Support.

Plan limits apply (for example, Free includes a small tag set). Changelog tags are separate and managed in **Settings → Changelog**.

Example uses:

| Category | Example tags |
|----------|--------------|
| Customer segment | Enterprise, SMB |
| Product area | Onboarding, Billing, API |
| Theme | UX, Performance, Security |

## Merge duplicates

When two requests are the same idea:

1. Open a request
2. Use **Merge** in the request toolbar
3. Choose **Merge into** another request, or **Merge here** to keep this one

Votes and comments are preserved on the primary request. Merged sources stay linked so you can see what was combined.

## Pin, lock, and feature

On a request you can:

- **Pin** it so it stays at the top of lists and roadmap columns
- **Lock** it to stop further comments
- **Feature** it to highlight it

## Roadmap status

Move work through Pending, Review, Planned, Progress, Completed, and Closed from the request or by dragging cards on the [roadmap](/docs/getting-started/plan-roadmap).
